# SurfaceForge 開發規格與交付計畫

> 本文件同時保存規格、目前摘要與歷史紀錄；實際結果以各階段驗證紀錄為準。2026-11-07 QA 現況：桌面 M1–M4、VR S0–S5 與 I1 additive Loading 已實作，PR #18／#19 已合併；本次只處理 QA，不開始 I2／Windows／D1／XR；依使用者最新釐清，允許透過 Unity Skills 進出 Play Mode、重現與執行自動測試，仍禁止 Computer Use 操作 Unity。詳見 [QA 紀錄](QABeforeI2.md)。

## 1. 目標與範圍

製作可調整視窗大小的 Unity 桌面應用程式：使用者從右側道具下拉清單拖曳三維道具，在具有高低起伏的有限曲面上放置，並能選取、刪除已放置道具。

最終交付為單一 Windows App：啟動後由場景選單選擇桌面版或 VR 鍵鼠模擬版進行驗收，並可返回選單。先完成桌面 M1–M4 與獨立 VR 模擬場景，再實作選單及整合驗收。交付包含執行檔、實際執行錄影、公開儲存庫連結及可回溯的階段提交紀錄。

VR 模擬規格詳見 [VRSimulationDevelopment.md](VRSimulationDevelopment.md)。S0 獨立場景、地形副本與 S1 角色移動已完成 Editor 基本驗證；S1 已獲使用者 Editor Play Mode 人工確認（陡坡人工測試略過），S2 左球面板已實作，技術驗證與人工確認狀態見 [S2 驗證紀錄](S2Validation.md)，S3 射線與 UI 路由已實作，實際測試與人工確認限制見 [S3 驗證紀錄](S3Validation.md)；S4 已實作，測試結果與人工驗收限制見 [S4 驗證紀錄](S4Validation.md)；S5 已實作，技術驗證與待人工確認見 [S5 驗證紀錄](S5Validation.md)；I1 選單、返回入口及 additive Loading 已實作，使用者已對 3a373fc 回報整體測試正常；逐項自動案例、比例及連續縮放仍未確認，建置留待 I2。

以上為開發採用的合理預設。開始實作前需再核對場景與既有程式碼，避免重複建置。

### Terrain 製作原則

- 直接使用 Editor 地形工具雕塑高地、低地與緩坡，不另外實作程序化曲面網格產生器。
- 使用單一、尺寸精簡的 Terrain，保留清楚可見的有限邊界；以攝影機構圖呈現高低落差與邊界外背景。
- TerrainData 作為專案資產保存並提交，Terrain 與 TerrainCollider 使用相同資料；高度圖解析度依展示需求設定，避免不必要的高密度。
- Terrain GameObject 指定為 `Surface` layer；放置以射線命中 TerrainCollider 為準，使用命中位置與法線。不能只用地形高度取樣判定合法放置，以免忽略邊界與無命中情況。
- 本需求不包含洞穴頂部、懸垂或多層曲面，採 Terrain 高度場即可滿足範圍。

## 4. 操作流程與邊界行為

### 4.1 道具清單

- 右側固定停靠面板包含標題與 dropdown 開關；展開後顯示圖示、名稱及可拖曳項目。
- 使用可放置拖曳項目的自訂展開面板，不強制採用只有文字選擇功能的標準 Dropdown。
- 清單過長時可捲動；只有超過拖曳門檻才開始建立預覽，避免普通點擊誤放置。

### 4.2 拖曳與放置

1. 從項目開始拖曳時，記錄道具定義並建立唯一一個預覽。
2. 每次更新先檢查該指標是否位於 UI，再由攝影機射線查詢曲面。
3. 使用專用 Surface layer 與有限距離查詢，排除預覽、已放置物件及其他裝飾物件。
4. 有命中時更新預覽與落點；無命中時以滑鼠射線上的固定深度呈現無效預覽，不沿用上一個合法落點。
5. 放開當下重新判定 UI 與命中結果；合法時建立一個正式物件，否則不建立。
6. 無論成功或取消，都清除預覽與拖曳暫存狀態；桌面版不實作指引線與落點標記。

預覽不阻擋射線、不具有互動碰撞；以材質或顏色區分合法與無效狀態。按 Esc、失去視窗焦點、停用拖曳控制器或切換模式時取消拖曳，避免殘留預覽。離開視窗後放開也不得造成下次回到視窗時意外放置。

道具 prefab 採底部中心為放置錨點；球體等模型以子物件偏移對齊錨點。以曲面命中點與法線計算根物件姿態，避免使用統一的世界 Y 偏移造成斜面穿插。基礎驗收以錨點位於曲面內為準，不額外要求整個道具底面不得跨出邊界；曲率較大時不宣稱完整貼合。

### 4.3 物件選取與刪除

- 僅在沒有拖曳且指標不在 UI 上時，接受場景選取。
- 以 PlacedProp layer 與碰撞器查詢物件；子碰撞器須能解析到所屬的已放置物件。
- 選單採螢幕空間 UI，從物件錨點轉換座標並加上間距，使選單出現在物件旁。
- 物件靠近畫面邊緣時將選單限制於畫布內；錨點位於攝影機後方時隱藏。
- 點擊空白處或開始新拖曳時關閉選單；點選另一物件時切換目標。
- 刪除按鈕處理有效目標後關閉選單，不讓該 UI 點擊穿透成為場景操作。

### 4.4 縮放與視窗比例

Canvas 使用 Scale With Screen Size，參考解析度 1920 × 1080，寬高匹配建議 0.5。右側面板使用右側錨點與上下伸展；清單內容用 Layout Group 與 ScrollRect 排版。避免以固定螢幕座標定位選單。

至少驗證 1280 × 720、1920 × 1080、1024 × 768 與寬螢幕比例，並測試執行中連續縮放。極小視窗下應透過捲動維持核心操作可達；不要求所有資訊同時顯示。

### 4.5 桌面滾輪縮放（2026-11-07 QA）

Main 的 TerrainOverviewCamera 保留地形與側欄自動取景，再乘以使用者縮放倍率；場景上滾輪向上拉近、向下拉遠，初始 1、範圍 0.35～1.5，每格 1.15 倍；程式初始換算為 120 wheel units，使用者試玩後將 Main 場景的 Wheel Units Per Step 設為 3（目前場景值）。UI 上、拖曳／左鍵持有、失焦、暫停及轉場期間不縮放；中斷後先等待無滾輪輸入的影格。倍率於元件重啟／場景重入回到 1，視窗縮放仍依當前倍率重新取景。不新增平移或滑鼠落點對焦。使用者已回報本輪整體測試正常；完整縮放矩陣與縮放自動案例仍未執行，詳見 [QA 紀錄](QABeforeI2.md)。

### 4.6 刪除選單動畫與繞行（2026-11-07 QA）

兩版刪除選單採 DOTween 淡入／淡出（預設 0.18／0.12 秒、unscaled time），關閉立即撤銷互動。VR 沿物件本地 Y 軸、在本地 XZ 平面繞行，保留朝向觀看者與物件前側偏上的位置；動畫不改定位或尺寸。詳細設定與未執行的回歸案例見 [QA 紀錄](QABeforeI2.md)。

## 5. 建議程式責任與資產結構

採簡單元件分工，不導入不必要的框架、全域服務定位器或大型事件系統。

| 元件 | 責任 |
| --- | --- |
| PropDefinition（ScriptableObject） | 穩定識別碼、名稱、圖示、prefab 與預覽設定 |
| PropCatalogView | 展開／收合清單與產生清單項目 |
| PropItemDragHandler | 將 UGUI 指標拖曳事件傳給放置控制器 |
| PlacementController | 管理 Idle／Dragging 狀態、預覽生命週期、提交與取消 |
| SurfacePlacementQuery | 射線查詢 Surface layer 上的 TerrainCollider，回傳命中點與法線 |
| PlacedProp | 標記正式道具與選單定位錨點 |
| PropSelectionState | 共用有效實例、子碰撞器解析、目標及單次刪除規則 |
| PropSelectionController | 桌面輸入及延後選取，轉接共用核心 |
| PropContextMenuView | 桌面物件旁選單、螢幕邊界限制及刪除操作 |
| SimulationSelectionController／SimulationContextMenuView | VR 選取轉接與世界空間名稱／刪除選單 |
| PlacementGuideView（VR 模擬） | 指引線與落點標記，隨 VR 拖曳狀態顯示 |

建議放在 `Assets/SurfaceForge/` 下，依 `Scenes/`、`Scripts/`、`Prefabs/Props/`、`Data/Props/`、`Terrain/`、`Materials/`、`UI/` 與 `Tests/` 分類。`Terrain/` 保存 TerrainData 與使用的 TerrainLayer 等資產；地形本身透過 Editor 製作，不需要專用生成元件。桌面使用 `Main.unity`，VR 模擬使用獨立的 `VRSimulation.unity` 與 TerrainData 副本；共用道具資產及放置規則，以明確 Inspector 參照連接。最後新增 `SceneMenu.unity` 作為 App 啟動入口。

## 6. 分階段開發與推送

各階段完成後進行實際驗證、提交並推送，不能等全部做完才建立公開遠端，也不能事後捏造開發歷程。提交應描述實際改動，不要求每個細小操作各自提交。

使用者要求審查 PR 時，依 [AGENT.md「Git 與公開交付」](../AGENT.md#git-與公開交付)預設透過 `@codex review` 請求 GitHub Codex Review，以繁體中文回報並追蹤實際審查結果；代理自行檢查不代替 Codex Review，不將送出請求視為審查完成，也不因審查完成而自行合併。

長任務依 [AGENT.md「額度檢查與暫停續作」](../AGENT.md#額度檢查與暫停續作)檢查訂閱額度；僅在 5 小時額度剩餘 10% 以下（含 10%）時，在安全節點保存進度至 `Docs/TaskCheckpoint.md` 並暫停，等待使用者輸入 `continue` 後重新確認額度與工作狀態再接續。每週額度不列入暫停判斷（2026-11-07 使用者釐清）。進度文件於實際需要暫停時建立，不自動恢復任務。

提交標題與內文、專案文件、開發紀錄、PR 標題與描述、代理自行撰寫的審查說明與回覆統一使用繁體中文，保留標準提交前綴及必要技術原文。既有紀錄可直接翻譯，不要求保留英文敘述，但不得改變歷史事實、驗證結果或 SHA、job ID 等參照；無權編輯的留言必要時另附中文說明。GitHub 自動產生的合併提交標題與內文為語言規則例外，可直接接受預設英文標題，不需每次合併手動翻譯；一般功能提交與 PR 內容仍使用繁體中文。需求或狀態變更時，依 AGENT.md 的文件一致性規則同步核對相關規格、README、驗收紀錄與 PR 描述。2026-11-06 的一次性歷史改寫及 SHA 對照詳見 [Git 歷史遷移紀錄](GitHistoryMigration.md)。

## 7. 驗證計畫

2026-11-07 規則釐清：禁止代理使用 Codex Computer Use 操作 Unity 圖形介面。允許代理透過 Unity Skills Editor API 或命令列讀取及修改場景、資產、程式與設定，執行編譯與 Editor／EditMode／PlayMode 自動測試，包括測試所需的進出 Play Mode。場景與資產修改優先使用 Unity Skills Editor API；使用前讀取協定並確認正確專案實例，不手改 Unity YAML。使用者負責進入 Play Mode 後親自點擊、拖曳、移動，進行畫面、手感與功能的人工驗收；代理提供步驟與預期結果。自動測試通過不能代替人工驗收，未取得使用者回報的人工項目仍標示「待使用者驗證」。此規則取代先前將 Unity 內自動測試也交由使用者執行的限制；下方歷史補記保留當時實際執行或未執行的事實，不因本次釐清改列通過。詳細規則見 [AGENT.md「驗證與完成定義」](../AGENT.md#驗證與完成定義)。

## 8. VR 模擬與實機 XR 的界線

鍵鼠 VR 模擬是已排定的獨立場景開發工作，不需要 XR 頭盔或額外 XR 套件。兩版完成後由場景選單整合交付；開發期間各自直接在 Editor 測試。

實機 XR 若另行開發，先選定一種確實可取得的裝置及目標模式，再確認相容套件；目前不得假設已安裝 XR Interaction Toolkit 或 OpenXR。

將桌面滑鼠與 XR 射線轉成共用的放置查詢與確認／取消意圖，重用道具資料和放置規則。XR UI 需可由控制器射線操作，並在目標裝置上驗證。切換前取消拖曳、清除選取，停用舊輸入與攝影機，再啟用新模式，避免雙重事件及多個有效 EventSystem。

實機 XR 若另行開發，需另外規劃 XR 子系統啟停及目標裝置驗證，不將鍵鼠場景選單視為已完成硬體模式切換。沒有硬體驗證時只交代架構準備與限制，不宣稱已完成裝置整合。
